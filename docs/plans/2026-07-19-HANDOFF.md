## 2. The design (device-cert model)

Read `docs/design/browserid-end-to-end-flow.md` — the canonical protocol overview.
In one paragraph: two IdP-signed device certs, `purpose`(authentication|
authorization) × `subject`(user|agent). An **authentication** device cert mints a
short-lived, fresh-key **access cert** at the IdP's mint API. A **config cert**
(authorization, client-side, non-extractable) signs a **warrant** over
`(identifier, subject) → audience[+scopes]`. The RP receives
`access_cert ~ assertion ~ warrant ~ config_cert` and joins by
`(identity, subject, audience)`. Every IdP MUST implement device-cert issuance +
the headless mint API (so agents mint with no browser). Warrants are always present.

**Hardening baked in (from the adversarial review — do not regress):** the config
cert MUST be issued by the identity's own IdP (`config_cert.iss == access_cert.iss
== identity's DNSSEC-authoritative IdP`); three fail-closed revocation authorities
(access→IdP, config→IdP, warrant→broker); primary/fallback conformance (a
fallback-issued cert for a domain that has a primary FAILS); `jti` single-use;
fail-closed on unknown purpose/subject.

## 3. What's built (device model — the KEEP side)

- `browserid-core/src/device.rs` — DeviceCert, AccessRequest, AccessCert,
  `device::Warrant`, AccessPresentation (+ `verify`). `browserid-core/src/jws.rs`
  holds the shared `jws_*`/`invalid`/`expired` helpers.
- **Frozen wire contract:** `test-vectors/device-cert-v1.json` — the `jws` fields
  are authoritative (Ed25519 deterministic). PHP/JS/Rust must reproduce them.
  Regenerate with `REGEN_VECTORS=1 cargo test -p browserid-core device::tests::golden_vectors`.
- Broker endpoints (`browserid-broker/src/routes/device.rs`): `POST /device/issue`
  (session; batch user+config certs, per-device status), `POST /access/mint`
  (headless), `POST /verify-access` (real conformance via
  `verifier.rs::verify_access_with_dns`), `GET /wsapi/device_certs` +
  `POST /wsapi/revoke_device_cert`, `POST /warrant/register`.
- DB: `device_certs` table + warrant `subject`/`config_cert` cols (`migrate_v12`);
  the chain tables were dropped in `migrate_v13`.
- Agent SDK: `browserid-agent` `DeviceAgent`/`DeviceCredential` (headless mint +
  4-object presentation); registrar `agent_provision.rs` device-cert mode.
- **sandmill.org primary** (`~/src/sandmill`, Laravel/PHP, deployed via
  `dokku@sandmill.org:sandmill`): `POST /api/browserid/device_cert` +
  `/api/browserid/access_cert`, discovery advertises them, **byte-compat proven**
  against the vectors (phpunit). NOTE: an API-JSON-forcing fix is still needed so
  browser `fetch` without `Accept: application/json` doesn't get a 302 redirect.

## 4. THE WORK — remove all old protocol

Follow `docs/plans/2026-07-19-old-protocol-removal-inventory.md` — the categorized
checklist (A core, B broker, C client, D registrar, E RP libs/SDK, F demos,
G consumers, H tests) with the KEEP-substrate list. Execution order:

1. **Login dialog (LOAD-BEARING) + fallback-IdP device issuance.** Rewrite
   `browserid-broker/static/{dialog.js, include.js}` so an RP-invoked login does:
   email → discovery (`_browserid` DNSSEC + `.well-known`) → route to the IdP's
   `/device_cert` (fallback = browserid.me SMTP; primary = popup to e.g. sandmill's
   endpoint) → `/access/mint` → sign the warrant with the config cert → return the
   4-object bundle to the RP. Convert `routes/fallback_idp.rs` to issue **device
   certs** (keep the SMTP email-verification; drop classic `cert_key`). This is the
   piece `dc-login` faked and the prerequisite for any real RP login. Do it for
   real (cold start, discovery-driven, no session shortcut).

   demo RPs (`examples/rp-quickstart`, `mcp-agent-auth`, `broker-demo`,
   `fallback-demo`).
3. **Registrar warrant** — `consent.rs` to config-cert `device::Warrant`; rebuild
   the device `/warrant/request` (removed in the chain cleanup).

## 6. Gotchas / lessons

- **Do NOT fan out parallel worktree/build agents** — it filled the disk mid-run
  (100%). Work sequentially. To free disk: `rm -rf ~/src/*/target
  ~/src/browserid-ng/.claude/worktrees` (all regenerable; worktree branches merge
  into main). Keep an eye on `df -h /Users`.
- Known-flaky: `browserid-agent`'s `consent_flow_test` (`browserid-ng-7v1h`,
  csrf/session race) — it's a LEGACY test being removed anyway.
- PHP↔Rust byte-compat gotchas (handled in sandmill, watch for consumers):
  `JSON_UNESCAPED_SLASHES`, struct-declaration field order (NOT the sorted display
  in the vectors file), `StatusRef {uri,idx}`, `PublicKey {algorithm,publicKey}`,
  header `{alg:EdDSA,typ:JWT}`.
- CSP: broker static pages under the Strict tier need external same-origin JS
  (no inline) OR an updated hash in `INLINE_SCRIPT_HASHES` (`routes/mod.rs`; the
  guard test `cargo test -p browserid-broker --lib csp` prints the needed hash).
- Beans: epic `browserid-ng-oup3`; DC phase beans (ga3w/ru87/thzq/xboy/qo3j/1ep4/
  umme/4qmg/zj2w); `browserid-ng-3b8m` (SBO relocation, gates the iframe delete).

Contact

Reach a person, not a ticket queue.

BrowserID is developed in the open by one person, so every channel below lands with someone who can actually fix your problem.

Bugs, questions, and ideas

The best channel for anything about the protocol, the hosted service, an SDK, or these docs is a GitHub issue — it's public, searchable, and other integrators benefit from the answer. Pull requests are welcome too; the whole stack, this website included, lives in the one repository.

Email

For anything that doesn't fit a public issue — account trouble, domain onboarding help, press, or just to say hello — write to code@sandmill.org. This is a small operation: you'll get a human reply, usually within a few days.

Security reports

If you believe you've found a security vulnerability in the protocol, the broker, or any SDK, please email code@sandmill.org with [security] in the subject line rather than opening a public issue, so a fix can ship before details are public. Reports are read with priority and you'll hear back about triage and timeline.

If you're an agent

Start at /llms.txt — it indexes every machine-readable resource on this site, including the OpenAPI spec and the MCP wallet endpoint. If your human needs to reach us, point them at this page.

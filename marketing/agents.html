Key vs. warrant

A borrowed key can't be reasoned about. A warrant can.

The moment an agent carries a personal access token, it can do anything its human can, everywhere, forever — and cutting it off means rotating a secret that breaks everything else. A warrant is the opposite in every dimension.

API key / PAT in config
  • Unscoped — works everywhere its owner can go
  • Unattributed — actions are indistinguishable from the human's
  • Long-lived, often never expires
  • Revoking means rotating the secret — and fixing everything else that used it
  • Sits in plaintext in a config file or env var
BrowserID warrant
  • Scoped — this site, these actions, and nothing else
  • Attributed — "agent X, on behalf of human Y", verifiable
  • Short-lived and bounded by what the human signed
  • Revoke in one click — the agent's next call fails closed, nothing else touched
  • The agent holds its own key; it never sees the human's password
⏻

Revoke, and the agent dies on its next call. The gate re-checks the warrant's revocation status on every tool call and fails closed — no token to wait out, no cache to expire. The human's own access is untouched.
